# 传感日志目录

字段沿用原 sensor CSV；fixtures/demo.json 给出设备、别名与校准配置。python demo_support/rotate.py /tmp/sensor-log start 写入半条记录，依次执行 rotate、tail、replace、truncate 控制后续变化，全部动作即时完成，不使用定时等待。跨行数值保留为可隔离原文，不要求数值解析器接受换行。生产跟随入口按目录运行，扫描和重试参数由产品接口说明。

## 采集器约定

入口为 `hangar_ingest.collector.pipeline.Collector`（CLI：`collect <目录> --source ... --name ...`）。

- 身份：以 inode + 世代（generation）追踪，不依赖路径。改名（rotate）后旧文件继续追加的尾部不丢；同名替换（replace）开新世代并把旧世代标为 `replaced`；同一 inode 截断重写（truncate，含等长重写）靠前缀锚点哈希识别，旧世代标为 `truncated`。
- 分帧：只在完整 CSV 记录处推进确认位置。引号字段可跨行；CR/LF 在引号外才结束记录；多字节 UTF-8 可在字符中间切开，EOF 的半条或未闭合引号留在 pending，下次随新字节重新分帧。
- 位置：`position` 为已确认字节位置，`read_position` 为磁盘读取高水位；恒有 `position + len(pending) == read_position`。
- 入库：完整记录走既有解码、校准、质量规则与批次流程；每行写入 `collector_lineage`（文件世代、路径、起止字节、原文）。业务写入与检查点同事务提交，崩溃后整体回滚，重启不产生第二份有效读数。
- 公平：单轮预算按文件独立分配（`budget_bytes`），一个高频文件最多用掉自己的配额，其他文件同轮仍被轮询。
- 端到端演练：`python demo_support/collector_drill.py`，覆盖半条、轮转、迟到尾部、崩溃重启、替换与截断，并打印批次、拒收原文、处理位置与字节血缘。
